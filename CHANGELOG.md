# Changelog

## [2.9.0] - 2026-11-04

- **New setting `clear_pushes` (default on):** after an approval or a reward is handled, FamilyMission removes the push from the other adults' devices with a silent `clear_notification`. The Companion app lists that command in its notification history. Settings card, tab "Benachrichtigungen" / "Notifications": "Erledigte Pushes auf den anderen Geräten entfernen". Off: no `clear_notification` is sent, handled pushes stay on the other devices. Validated like the other push switches (invalid value = on). README, parents' guide (de/en/fr) and in-app help updated.
- Tests: `tests/test_push_dedupe_ws.py`.

## [2.8.4] - 2026-11-04

- **Fix, duplicate pushes:** when several adults reach the same notify service (for example two parents with the same phone as push target, or a manual target that equals another adult's Companion app device), every push such as "✅ Kind ist fertig" arrived once per adult, and so did the silent `clear_notification` command after approving (it shows up as "clear_notification" in the Companion app's notification history). Each notify service now gets a push and a clear command once.

## [2.8.3] - 2026-11-03

- **Fix, medication check in the kids card:** the button "✓ Genommen" / "✓ Taken" carried the check mark in its label, so it looked preselected next to the empty "Heute nicht" button and a kid could just tick through. Both buttons are now neutral and equal; the check mark appears only after "Genommen" was actually chosen. Nothing is preselected, an unanswered medication still blocks "Fertig!".

## [2.8.2] - 2026-11-02

- **Fix, kids card `mode: mine`:** "Heute erledigt" / "Done today" in "Meine Aufgaben" now also lists the adult's own completed parent tasks (before, only point tasks appeared, so the count differed from the parents card). Parent entries show no stars; undo asks "… rückgängig machen? Die Aufgabe ist dann wieder offen." instead of mentioning points.

## [2.8.1] - 2026-11-02

- **Parents' hub, More → Parent tasks:** one-time to-dos (quick add, someday, dated; they are deleted when ticked off) are no longer listed between the recurring parent tasks. They sit in a collapsed fold "Einmalige To-dos (N)" / "One-time to-dos (N)" below the list, so the "who does what" list stays short.

## [2.8.0] - 2026-11-02

- **Quick to-do on the own device.** In the kids card with `mode: mine`, an adult with a parents' role gets a round **＋** (44 px) in the "Meine Aufgaben" header. It opens a kids-style sheet: name (autofocus, Enter creates), chips Heute / Morgen / Wochenende / Datum / Irgendwann, optional time (15-minute select) and, when a partner exists, "Für" me / partner. The task is created with the existing `family_mission/parent_task_add`; errors show a toast and keep the sheet open. Never shown for kids or on the shared tablet.
- **Parent tasks in "Meine Aufgaben":** overdue dated tasks show a red "seit Mo" badge, every task has "→ Morgen" (`parent_task_postpone`), future dated tasks are listed in the fold "Demnächst (N)" and tasks without a date in "Irgendwann (N)" (same grouping as the parents card).
- Night mode does not affect the own-device view (unchanged). de/en strings, README, help and parents' guides (de/en/fr) updated.
- Tests: `tests/test_mine_quickadd_ws.py`.

## [2.7.0] - 2026-11-02

Sticky footer (Löschen / Abbrechen / Speichern); full-screen sheet with collapsed rows on phones; light / dark theme, 44 px touch targets, aria-pressed on segmented buttons.
- **Removed from the forms:** the recurring / one-time switch of the task dialog (Wann > Einmalig covers it), the HA area picker (a stored `area` is kept on save) and the raw mdi text field. Pause, own overdue limit and a fixed due date stay available in the household card under "Erweitert".

- Tests: `tests/test_frontend_assets.py` checks the new asset and its registration.

## [2.6.0] - 2026-11-01

- **Fix: a quick-start re-run no longer resets your customizations.** Re-running the wizard with "Bisherige Assistent-Aufgaben abgleichen" (`replace_existing`) used to overwrite name, points, icon, category, age, times, interval and steps of every wizard task and to delete wizard tasks that were deselected. Now every edit of a wizard task (`edit_task`, `edit_task_by_name`, the task dialogs) records the changed definition fields in `task["customized"]`; the wizard only updates the fields that are not listed there. Progress toggles, completion, due date, pause, claim and the rotation turn are no customization. Wizard tasks from before are compared with the catalog once on load (`kids_catalog.legacy_customized_fields`, conservative: whatever is not the wizard's own value counts as customized).
- **Wizard: customized tasks are detached, not deleted.** A customized task that is no longer selected becomes an own task (`generated_by`, `wizard_key`, `customized` dropped, everything else kept, its device trigger follows by `task_id`); uncustomized deselected tasks are removed as before. New optional `reset_customized: [task ids]` in `wizard_apply` resets chosen tasks deliberately. The wizard never sets `interval` on a task with `weekdays` any more.
- **Wizard preview and summary:** `wizard_preview` returns `existing` (per earlier wizard task: customized fields and the planned action) and `existing_counts`; `wizard_apply` returns `kept_customized` and `detached`. The summary step shows "N angepasste Aufgaben bleiben unverändert · M werden aktualisiert · K werden entfernt · J werden zu eigenen Aufgaben" with an expandable list and an unchecked "auf Vorschlag zurücksetzen" box per customized task; the switch is now called "Bisherige Assistent-Aufgaben abgleichen (eure Anpassungen bleiben erhalten)".
- **Undo for the wizard:** before each run the changed / removed / detached tasks are saved in `data["wizard_backup"]`; new websocket `family_mission/wizard_undo` (admin / manager) restores them and removes what the run created (7 days or until the next run, goals and triggers are not restored). The first wizard screen offers "Letzten Assistenten-Lauf rückgängig machen".
- **Morning mission steps:** the catalog's morning mission now has "Frühstücken" and "Zähne putzen" (Anziehen, Frühstücken, Zähne putzen, Bett machen, Schlafanzug weg). Thanks to the protection this only reaches uncustomized missions on a re-run.
- **Catalog steps for (almost) every task:** all catalog entries except "Spülmaschine ausräumen" (unchanged) now bring 2-6 steps, de/en, each with an optional `min_age` / `requires` that is honoured in the wizard proposal, `flow_catalog` and the "New task" sheet (`flow_catalog(lang, features, age)`, each step carries `min_age`; `kids_catalog` returns `kid_ages` so the sheet leaves out steps the youngest selected kid is too young for). Morning mission: + "Brotdose & Trinkflasche einpacken" (from 8, needs school); evening mission: + "Zähne putzen", "Schlafanzug an", "Kleidung für morgen rauslegen" (from 8); room blitz / small / thorough, table set / clear, dishwasher load, plants, garden, driveway, pets, laundry, bedding, dryer, washer, robot vacuum prep, trash, groceries, bottles, cooking, car, windows and sink got their steps.
- **Old step lists stay "uncustomized":** `kids_catalog.LEGACY_SUBTASKS` freezes the previous lists (including the morning mission before "Frühstücken" / "Zähne putzen" and entries that had no steps); `legacy_customized_fields` accepts them next to the current list, so on a re-run only uncustomized tasks receive the new steps (customized ones are protected as before).
- **Medication step position:** new optional care field `after` (title of the mission step it follows, at most 60 characters, `""` = at the end, validated in `kids.normalize_care`). Default: after "Frühstücken" / "Have breakfast" in the morning mission (if present), otherwise at the end. Same order in the kids card (`kids.care_insert_index` / `care_merge_steps`, mirrored in the card). Settings card care editor and the parents card medication sheet get a select "Position: nach Schritt ..." with the steps of the kid's mission and "am Ende".
- **Tests:** new `tests/test_wizard_protect_ws.py`, pure tests for `legacy_customized_fields` in `tests/test_kids_catalog.py`; existing wizard tests adjusted (new morning steps, new apply counters, `requires_approval` of a customized task is kept).
- **Parents' "Meine Aufgaben" as a task list:** a **＋** in the section header opens a quick-add sheet (name, Enter creates; date chips Heute / Morgen / Wochenende / Datum / Irgendwann; "Mehr Optionen": time, repeat, minutes, planning). The list is grouped into Überfällig / Heute / Demnächst / Irgendwann plus the fold "Heute erledigt"; every task has ✓, **→ Morgen** and a due date / time badge.

A one-time task with a date becomes open on that day and stays overdue until done (not carried over silently, flag `dated`); without a date it is a "someday" task (`someday`, `due_date: null`). Recurring tasks and existing parent tasks keep their behaviour. **Note:** `parent_task_add` with `interval: 0` and no date now creates a someday task (before: due today).

## [1.0.0] - 2026-10-31
First FamilyMission release, based on TaskOrganizer 1.7.0 (MIT, Patrick von Wiegen, https://github.com/patrickvonwiegen/TaskOrganizer).

### Project
- New domain `family_mission`, own storage (`family_mission.storage`), own services, events, websocket commands, entities, card names (`custom:family-mission-*`) and push action prefixes (`FM_`). Runs next to an installed TaskOrganizer without any conflict.
- **Automatic migration:** on the first start without own data the data and options of TaskOrganizer are copied (read only, once), with a persistent notification that lists what to adapt. Admin-only service `family_mission.import_from_task_organizer` (`overwrite: true`) repeats the import on purpose.

### Features
- **Family missions:** tasks and templates with intervals, points, subtasks, categories (`basis`, `bonus`, `auftrag`), minimum age, time windows, reminders and "together" mode.
- **Kids' wall tablet:** `family-mission-kids` with kid tiles, progress ring, PIN pad (brute-force lockout), bonus board, family rocket, confetti and sounds.
- **Own-device view:** `mode: mine` for the person linked to the logged-in Home Assistant user.
- **Parents card and roles:** approvals, "not done" / "cheated", bonus points and deductions, undo, parent roles (admin, manager, parent).
- **Reward shop:** per-kid wallet, configurable rewards, savings goal, redemptions with push approval.
- **Praise:** stickers and messages without points.
- **Quick-start wizard:** age-appropriate task packages, rotating duties and monthly goals from a built-in catalog.
- **Bonus triggers**, monthly goals, leaderboard, reports and a history protocol.
- **In-app help** (parents guide) in German, French and English, plus Markdown versions in `docs/`.
